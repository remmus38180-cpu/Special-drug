# 特殊藥品認定、調高及供貨合約管理系統　使用說明（v0.4.0）

本說明對應單一檔案程式 `特殊藥品管理_v0.4.0.html`（資料結構版本 1）。程式完全離線執行：不連網、不上傳、不安裝；資料只存在你選定的資料夾。機關電腦尚未完成實地驗收的項目，見 `docs/驗收結果_v0.4.md`「待實地驗收」。

---

## 1. 第一次使用

1. 將 `特殊藥品管理_v0.4.0.html` 放在共用槽或本機任一位置，以 Edge 或 Chrome 開啟（雙擊或拖進瀏覽器）。不需安裝、不需系統管理員權限。
2. 畫面下方「啟動自檢」列出瀏覽器能力。須全部通過才能編輯；「資料夾存取」不支援時只能唯讀查詢備份 zip（第 9.3 節）。
3. 輸入「員編／姓名」及「電腦代號」，按「儲存使用者」。
   - 瀏覽器基於安全限制讀不到 Windows 登入帳號與電腦名稱，所以要自己輸入。名稱存在這個 Windows 帳號的瀏覽器設定中，下次自動帶入；換人登入同一台電腦須重新輸入。
   - 此名稱只供畫面顯示與稽核紀錄，**不是身分驗證**。
4. 建立資料夾：在共用槽建一個**空資料夾**（例：`\\伺服器\共用\特藥系統\資料\`），按「建立新資料夾（選空資料夾）」選它，並設定「強制收回關鍵詞」（第 4 節）。
   - 想先試用：建另一個空資料夾，進入編輯後於首頁按「載入示範資料」。示範資料只能載入到新資料夾，載入後該資料夾永久標示「示範資料夾（非正式資料）」。**不要在正式資料夾載入示範資料。**
5. 之後每次使用：按「開啟資料夾」或「重新授權上次資料夾」。瀏覽器重開後須再按一次授權（瀏覽器規定，非程式錯誤）。

## 2. 資料夾裡有什麼

| 路徑 | 內容 | 可否手動改 |
|---|---|---|
| `specdrug.json` | 資料夾識別（folder_id、建立者、資料結構版本） | 否 |
| `control/editing.json` | 編輯牌（目前持牌者、心跳） | 否 |
| `control/keyword.json` | 強制收回關鍵詞之加鹽雜湊（無明文） | 忘記關鍵詞時可刪除（第 4.4 節） |
| `data/current.json` | 指向目前版本檔 | 否 |
| `data/versions/r000123-…json` | 每次儲存一份完整版本（含稽核雜湊鏈），一次寫入、不覆寫、不刪除 | 否 |
| `masters/<id>.json` | 各主檔版本之列資料 | 否 |
| `attachments/xx/<SHA-256>` | 附件、主檔來源檔、移轉來源檔原件（以雜湊為檔名） | 否 |
| `logs/export-log.jsonl` | 匯出紀錄 | 否 |

- 程式開啟時會驗證版本檔雜湊與稽核雜湊鏈。若有人用外部程式改過檔案，開啟時會列出位置並拒絕自動採用，不靜默修正。
- 版本檔會隨儲存次數增加，**程式不自動刪除**。保存期限與封存方式由單位決定（Q09）。

## 3. 查詢與編輯、儲存

- 開啟資料夾後是**查詢模式**（唯讀）：可查詢、匯出、下載附件。多人可同時開啟查詢。
- 要修改資料：按「開始編輯」取得**編輯牌**。同一時間只有一人能編輯（第 4 節）。
- 編輯中的變更先成為「未儲存變更」（狀態列顯示筆數），同時自動存成本機**復原草稿**（存在這台電腦的瀏覽器裡）。按「儲存」才寫入資料夾成為新版本（revision＋1）。
- 儲存時程式會：①確認編輯牌仍在自己手上 ②確認資料夾沒被其他人存過新版 ③檢查資料一致性與引用檔案 ④寫入新版本檔並讀回驗雜湊 ⑤更新 `current.json`。任何一步失敗都不改目前版本，變更保留在復原草稿。
- 狀態列常駐顯示：資料夾、模式、編輯牌持有者、目前 revision 與儲存時間、未儲存變更數、目前主檔版本。查詢模式每分鐘檢查一次，有新版會提示「重新載入」。
- 有未儲存變更時關閉分頁，瀏覽器會先提醒。

### 3.1 當機或斷電後復原

重新開啟同一資料夾時，若本機有復原草稿，程式會提示：
- 草稿基準與資料夾目前版本相同：按「取得編輯牌並復原」取回未儲存變更；或「放棄草稿」。
- 資料夾已有更新版本（別人存過）：**不會自動套用**。可按「另存為復原檔」存成 JSON 檔供核對，再手動重做需要的變更。

復原草稿只存在原來那台電腦、原來那個瀏覽器；換電腦不會跟著走。

## 4. 編輯牌：多人查詢、一人編輯

### 4.1 怎麼取牌、還牌

- **取牌**：按「開始編輯」。牌沒人拿就取得（程式會等 3 秒確認沒有同時搶牌）；牌在別人手上會顯示「編輯牌目前在 ○○○（電腦：○○）手上，自 10:12 起，最後回應 10:45」，可繼續查詢、重新檢查或強制收回。
- **還牌**：
  1. 按「結束編輯」（有未儲存變更會先問要儲存、保留草稿或放棄）。
  2. 關閉分頁或瀏覽器時，程式會嘗試自動還牌。
  3. 當機、斷電、強制結束、斷線、電腦休眠時來不及還牌：持牌者**超過 5 分鐘沒有回應**，別人即可直接取牌，不需關鍵詞，畫面會列出前一位持牌者。
- **本機已關閉分頁**：同一台電腦、同一瀏覽器，前一個分頁已關閉但來不及還牌時，新分頁可直接取牌（單人使用設定，已啟用）。

### 4.2 強制收回

持牌者程式仍開著、但需要接手時，按「強制收回」，輸入關鍵詞及原因。被收回者在 30 秒內自動轉為查詢模式並收到提示（收回者、時間、原因），其未儲存變更保留為復原草稿。連續輸錯 5 次，30 秒內不能再試。

### 4.3 限制（必讀）

1. **編輯牌是程式之間的約定，不是檔案伺服器仲裁的獨占鎖**（瀏覽器沒有這種能力）。兩人在數秒內同時取牌、或網路磁碟快取延遲時，仍可能兩人都進入編輯。此時由儲存前後的檢查，使後存者被拒絕或立即警告，已存版本不會被靜默取代，但後存者可能需要人工重做變更。
2. **關鍵詞存在共用資料夾內**；有資料夾寫入權的人若直接改檔，可以繞過關鍵詞。關鍵詞用來防止誤按與隨意搶牌，**不是資安控管**。
3. 真正由伺服器把關的只有共用槽權限：建議只給需要編輯的人寫入權，其他人唯讀。程式偵測到資料夾不可寫入時只提供查詢模式。
4. 心跳 30 秒、視為關閉 5 分鐘、輸錯 5 次鎖 30 秒為預設值，可在「設定」調整（Q13）。

### 4.4 修改或忘記關鍵詞

- 修改：設定頁「修改關鍵詞」，須輸入原關鍵詞。
- 忘記：由具資料夾寫入權者刪除 `control/keyword.json`，下次開啟時程式會要求重新設定，並記入稽核（Q16 暫採方案）。

## 5. 業務操作流程

### 5.1 案件與會議

- 「案件」頁：新增案件（收文日、文號、主旨、申請廠商、申請事項、品項）。未通過、撤回、辦理中的案件都要建；不需要先有認定。歷史資料未知欄位可留空，系統標示完整性「待確認」。
- 「會議」頁：建立會議（專家／藥事小組／共同擬訂／其他），同一次會議可加多個案件的議案；每個議案登錄專家建議或會議決議，並可逐品項登錄結果（同意、不同意、附條件同意…）。專家建議與會議決議分開標示，不互相覆蓋。
- 案件結果摘要須選擇依據的決議後確認；結案須填原因與依據。

### 5.2 主檔匯入

1. 「主檔」頁選檔（.xlsx 或 UTF-8 CSV；不支援 .xls）。選預設映射：
   - **月產製藥品主檔**：支付價欄依資料基準日自動預選（例：price11511）。
   - **日產製 DWM_DRUG**：需另選 `DWM_DRUG_RCODE` 代碼檔；價格可用 `DWM_DRPAY` 長表依基準日取價。
2. 選用檔案：
   - `DWM_DRUG_RCODE`：提供規格單位清單（type 2）。
   - **藥品許可證檔**：用於「同申請商（同廠牌）」條件。至食藥署開放資料下載「藥品許可證」資料集（資料集 36，網址 `https://data.fda.gov.tw/data/opendata/export/36/csv`，下載為 zip），直接選 zip 或其中的 CSV。系統不連網，須自行下載。未提供時，同申請商條件一律判待確認。
3. 填資料基準日，按「試匯入」。檢核結果列出代碼錯誤、同代碼矛盾（阻止啟用）、完全相同重複（勾選確認合併）、未知單位、許可證對應筆數等。試匯入不改目前主檔。
4. 確認後「啟用」：來源檔存為附件、列資料寫入 `masters/` 並驗雜湊，舊主檔版本改為「已停用」（保留，可比對）。
5. 規則：主檔「必要藥品」空白視為 0（一般藥品）；範圍全域排除代碼前綴 TPN 及不上網註＝Y（設定頁可調）；分組代碼空白直接視為不符合。

### 5.3 規則預覽、認定與快照

- 「規則預覽」頁可先試條件：常用範本（依分組、依 ATC 加劑型、依分組加規格、指定品項、進階）、條件群組（全部符合／任一符合／排除／同申請商另有品項）。條件值從主檔清單點選，貼上多值時標示主檔無此值。
- 「認定」頁：新增認定項目（同名不可重複，變更請建新版本）→ 新增版本（類別、期間起日含迄日不含、依據決議）→ 編輯適用條件 → 以目前已啟用主檔預覽 → 保存為快照 → 待確認品項逐筆或依原因批次「納入／排除」（須填理由）→ 確認快照 → 確認認定版本。
- 已確認的認定以新主檔建立新快照擴大範圍時，確認畫面會列出新增品項；新增品項不會自動調高或註記。
- 與其他認定類別衝突時須填處理依據；查詢時衝突品項不給單一類別。
- 分組調價方式：快照只涵蓋部分分組時，該分組改依第 25 條須填依據；方式非「待確認」者須有適用起日才可確認。

### 5.4 公告與合約

- **合約**：新增合約（編號、廠商、簽訂／生效／到期日、文件版本、供貨義務、狀態、適用品項），上傳附件；補充協議以「新增補充協議／新版」建立，原合約保留。到期前 60 日列提醒，只提醒、不自動取消任何資料。合約已被已確認調高引用時仍可修改，但須填原因（Q11 暫採）。
- **公告複核登記**：選已確認的認定版本 → 從範圍名單**勾選本次調高品項**（範圍外不能勾）→ 登錄簽約要求、對應合約、調高前後價格、生效日、公告文號與日期、辦理狀態，可同時建立「新增」註記（註記生效日與調高生效日分開填）→ 核定後勾選並「確認公告」，可附公告文件。
  - 須簽約者：合約須「完成簽署」且含此品項；不檢查合約起訖（B18）。
  - 「當時無須簽約」須填依據；「待確認」可確認但標示不完整（B17）。
  - 整批確認：任一筆不通過或附件寫入失敗，整批都不成立。
  - 已確認的調高不能改，請用「更正」建立更正紀錄（原紀錄保留）。
- 註記取消、更正須逐筆登錄並填依據，不批次取消。

### 5.5 查詢、差異待辦、匯出

- 「品項查詢」：輸入藥品代碼與日期，列出主檔資料、當日認定類別、認定版本、案件與每次會議結果、範圍快照、調高、合約、註記、差異待辦。
- 「差異待辦」：啟用新主檔後按「依目前主檔產生差異待辦」，列出新符合、不再符合、分組異動、主檔消失、規則停用；每筆選「已處理／不處理」並填結論。
- 「主檔註記比對」：以主檔必要藥品註記（3＝不可替代特殊藥品、4＝特殊藥品，可於設定調整）與系統已確認註記比對，結果分一致、應有未有、主檔有但無完整依據、類別不同、無法判定；不一致可轉為差異待辦。本系統不直接更新正式主檔。
- 匯出：認定清單、品項明細、差異待辦、比對結果、移轉核對清單。以另存對話框帶入預設檔名 `特藥_<內容>_<台北時間>_r<revision>.xlsx`；有未儲存變更時檔名加「+未儲存」並先提示。xlsx 第一頁「匯出說明」記錄版本與條件；CSV 檔首 `#` 說明列（設定可關閉，改產 `_說明.txt`）。
- 每次匯出記入 `logs/export-log.jsonl`。檔案被改名後，可在「儲存歷程」頁「依檔案反查來源版本」查出它來自哪個版本與條件。
- 表格：點表頭可排序（只排序目前畫面顯示之列，分頁時不含其他頁）；捲動時表頭固定。
- 列印：瀏覽器列印（Ctrl＋P）時，每頁頁尾印出程式版本、資料 revision、列印時間及頁次。

## 6. 備份與還原

### 6.1 匯出備份

「備份還原」頁按「匯出備份」，產生 `特藥_備份_<時間>_r<revision>.zip`。內含目前**已儲存**版本、`current.json`、`specdrug.json`、所有被引用之主檔列資料與附件，及 `backup_manifest.json`（每檔路徑、大小、SHA-256）。不含編輯牌與關鍵詞。產生後程式會重讀逐檔驗證。

- 程式不在背景自動備份。建議：大量匯入（主檔、Excel 移轉）前先備份；備份檔另存他處（異地存放依單位規定）。
- 也可直接複製整個資料夾作為備份（須在無人編輯時複製）。

### 6.2 驗證與還原

- 「驗證備份檔」：檢查路徑（不得含 `../`、絕對路徑）、版本檔恰一份、清單外檔案、雜湊、資料引用、稽核雜湊鏈。
- 「從備份還原…」：須持有編輯牌、無未儲存變更並填原因。還原結果成為新版本（revision＋1），舊版本檔全部保留，可在「儲存歷程」唯讀開啟比對。資料夾內已有同名但內容不同的檔案時，整個中止、不寫入。
- 還原演練：先「建立新資料夾」，在新資料夾內還原。
- 備份時點之後的資料：還原後不在目前版本中，但舊版本檔仍保留可查（Q12 暫採）。

### 6.3 無法存取資料夾時唯讀查詢

瀏覽器不支援資料夾存取（或被群組原則停用）時，啟動頁按「開啟備份zip（唯讀查詢）」，可查詢與匯出，不寫入任何資料夾。

## 7. Excel 移轉（活頁簿1）

1. 「Excel移轉」頁選活頁簿（工作表 final），先看解析預覽（類別對照、待確認問題數）。
2. 「暫存」：來源檔存為附件；同一檔案、同一列不會重複暫存。
3. 逐列核對：看類別（原文→現行名稱）、規則草稿、待確認問題，按「寫入」或「略過」（須理由），也可勾選多列「寫入勾選列」。
4. 寫入建立：歷史案件（`HIST-…`，不完整）、會議議案（結果待確認；同類型同名同日的會議共用）、認定**草稿**版本、取消候選版本。不產生有效認定、調高或註記。
5. 之後仍須：補生效日與依據、以主檔預覽建立快照、人工核對範圍、確認認定。
6. 特例：Rufinamide「參考特殊藥品精神調高、非認列」只保留案件與原文，不建立認定。Warfarin「同廠牌」依使用者確認改為「同申請商」條件，須匯入許可證檔。
7. 合併候選（同公告序號、公告名稱或分組代碼）只列出供核對，系統不自行合併。

## 8. 換電腦、搬移資料夾、程式更新

- **換電腦**：新電腦開啟 HTML → 輸入員編與電腦代號 → 開啟同一資料夾並授權。復原草稿不會跟著搬。
- **搬移資料夾**：先在原電腦結束編輯並儲存，關閉所有開啟此資料夾的分頁，再整個資料夾複製到新位置（含 `control/`、`data/`、`masters/`、`attachments/`）。新位置開啟後重新授權。不要只複製部分子資料夾。
- **程式更新**：以新版 HTML 取代舊檔即可，資料夾不需變動。新版若升級資料結構，舊版程式開啟新資料夾時只能唯讀，並提示更新程式。資料結構目前為第 1 版，尚無升級程式；日後升級時會隨新版程式提供並先要求備份。
- 程式版本：標題列、「關於」頁、`<meta name="version">` 與檔名皆標示程式版本、資料結構版本、建置日期及原始碼 commit。

## 9. 設定項

| 設定 | 預設 | 說明 |
|---|---|---|
| 心跳間隔（秒） | 30 | 持牌者更新編輯牌的頻率 |
| 視為已關閉（分鐘） | 5 | 超過即可直接取牌；須至少為心跳 3 倍 |
| 關鍵詞連續輸錯次數／鎖定秒數 | 5／30 | |
| CSV 加說明列 | 是 | 關閉時另產 `_說明.txt`（供 SAS 等直接讀入） |
| 附件大小上限（MB） | 50 | |
| 範圍過大警示門檻（筆） | 500 | |
| 範圍全域排除：代碼前綴 | TPN | 逗號分隔 |
| 範圍全域排除：不上網註＝Y | 是 | |

設定變更也是未儲存變更，按「儲存」後生效並留稽核。

## 10. 常見訊息

| 訊息 | 原因與處理 |
|---|---|
| 未取得資料夾讀寫授權 | 瀏覽器重開後須重新授權：按「重新授權上次資料夾」 |
| 此資料夾不是本系統資料夾 | 選錯資料夾；建新資料夾請選空資料夾 |
| 資料夾無寫入權，只提供查詢模式 | 共用槽權限唯讀；需編輯請向管理者申請寫入權 |
| 資料夾已被其他分頁或程式變更 | 別人已存新版：按「重新載入」核對，變更保留在復原草稿 |
| 編輯牌已不在本工作階段 | 被強制收回或逾時被他人取得：已轉查詢模式，變更在復原草稿 |
| 編輯牌狀態不明 | 心跳寫入失敗（斷線）：暫停存檔，恢復連線後自動重新確認 |
| 稽核雜湊鏈中斷／雜湊不符 | 檔案被外部改過：不要繼續編輯，請以備份還原或聯絡維護者 |
| 須簽約但未對應合約（缺件） | 選對應合約，且合約須完成簽署並含此品項 |
| 不在此認定已確認的範圍名單內 | 範圍外品項不可直接調高，須另補認定依據 |

## 11. 已知限制

- 編輯牌非伺服器獨占鎖、關鍵詞非資安控管（第 4.3 節）。
- 使用者名稱為自行輸入，非身分驗證；伺服器端可由檔案擁有者核對（Q15，待實測）。
- 復原草稿只存在原電腦瀏覽器。
- 不支援 .xls；Excel 列數上限 1,048,576 列，超過請用 CSV。
- 不在背景自動備份；版本檔不自動清除。
- 列印頁次需瀏覽器支援列印頁邊（Edge／Chrome 新版支援）。
- 本程式未使用任何第三方函式庫（ZIP、DEFLATE、xlsx 讀寫、十進位運算皆自行實作），故無外部授權檔。xlsx 檔案格式內必須寫入的 XML 命名空間字串（如 `http://schemas.openxmlformats.org/…`）只是格式識別，不會連線。
- 機關電腦尚未實測：防毒掃描、`file://` 與共用槽開啟、群組原則、兩台電腦取牌、效能等，見 `docs/驗收結果_v0.4.md`。
