# 操作與維運說明

## 1. 部署

1. Windows 開發機：`tools\build_windows.bat` → `dist\specdrug\`。
2. 共用槽建立 `app\0.1.0\`，複製整個 `dist\specdrug\` 進去（程式更新放新版本資料夾，不覆寫使用中的版本）。
3. 同資料夾放 `config.json`：`{"store_root": "\\\\伺服器\\共用\\specdrug"}`。
4. 檔案伺服器 ACL：
   - 查詢者：`releases/ attachments/ control/` 唯讀（`control/edit.lock` 需可開啟讀取）。
   - 編輯者（登記者／複核登記者）：上述目錄可寫入＋`staging/ backups/`。
5. 管理者首次啟動 → 初始化（自動跑環境驗證，未通過不初始化）→「稽核／管理 → 帳號設定」加入同仁 Windows 帳號（`網域\帳號`）與角色。管理者不自動具核定權，須另勾「複核登記者」。

## 2. 日常

- 查詢：直接開啟即可；橫幅顯示目前版本、編輯者。有新版時按「重新整理」。
- 編輯：「開始編輯」→ 修改（自動存本機草稿）→「發布」→「結束編輯」。
- 主檔：每月或需要時「主檔匯入 → 試匯入新主檔」→ 選預設映射 → 指定資料基準日 → 檢核 → 啟用 → 產生差異待辦。
  - 月產製檔：選「dwm_drug 月產製處理檔」，支付價欄選與基準日相符的 priceYYYMM。
  - SQL Server 每日檔：從 SQL Server 匯出 DWM_DRUG、DWM_DRUG_RCODE、DWM_DRPAY 為 xlsx 或 UTF-8 CSV（超過 104 萬列請用 CSV），選「DWM_DRUG SQL Server每日檔」，再選代碼檔與價格長表。
- 公告複核：認定頁建立版本 → 規則編輯／預覽 → 建立快照 → 人工確認待確認項 → 確認範圍名單 → 確認版本 →「公告複核」勾選本次調高品項 → 核定後補文號日期 → 驗證 → 確認 → 發布。

## 3. 鎖定與復原

| 情況 | 處理 |
|---|---|
| 顯示「其他人正在編輯」 | 看橫幅編輯者，聯繫對方結束編輯。 |
| 編輯者程式當機／關機 | 重開程式按「開始編輯」：鎖由檔案伺服器在連線關閉後釋放；本機草稿自動復原（基準未變時）。 |
| 鎖疑似殘留（對方已關機仍無法取得） | 管理者須在檔案伺服器「開啟的檔案／工作階段」確認並關閉舊控制代碼後才可再取得；**不得刪除 `control/edit.lock`**，無法確認就維持只讀。 |
| 編輯中斷線 | 程式禁止寫入與發布；選「結束編輯→保留本機草稿」。恢復後重新開始編輯：若期間他人已發布，舊草稿移到 `%LOCALAPPDATA%\specdrug\recovery-*`，請核對後重套變更。 |
| 發布中斷線 | 再按「發布」：以同一操作 id 判斷是否已成為版本，只會有一次有效發布。 |
| `staging\*.partial` 殘留 | 未完成發布，不會被讀取；管理者可於無人編輯時刪除。 |

## 4. 備份與還原

- 每次發布即保存完整不可變版本（`releases\`）。
- 「稽核／管理 → 備份目前版本」（限管理者）：複製版本資料庫、manifest、所有引用附件到 `backups\backup-*`，並驗證雜湊。大量匯入前請先備份。
- 機關排程每日備份：複製 `releases\<current.json 指向的版本>`、`attachments\`、`control\current.json` 即可；**不要複製本機工作資料庫**。
- 還原（限管理者）：取得編輯權 →「還原備份」→ 選備份資料夾、填原因 → 以新版本發布舊內容（歷史版本不改寫，稽核記錄還原原因；還原前現行版本的稽核紀錄全數併入，不重複）。
- 復原演練：還原後以「品項明細」抽查認定、快照、合約附件可開啟。

## 5. 設定（`settings` 表，管理者）

| key | 說明 |
|---|---|
| annotation_code_map | 認定類別↔主檔必要藥品註記 DRUG_NECESSARY 代碼（預設 不可替代特殊藥品→3、特殊藥品→4） |
| unit_conversions | 經確認的單位換算，如 `{"L": ["ML", 1000]}`；預設空 |
| known_units | 已知規格單位；不在清單者判待確認 |
| large_scope_threshold | 規則預覽過大範圍警示門檻（預設 500） |
| attachment_max_mb / attachment_allowed_ext | 附件上限與類型 |
