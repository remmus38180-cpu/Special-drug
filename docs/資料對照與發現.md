# 資料對照與真實資料檢查發現

依使用者說明：`dwm_drug_11509.xlsx` 為**每月產製的處理後資料**；`DWM_DRUG／DWM_MULTIPLE／DWM_DRUG_RCODE` table layout 為 **SQL Server 每日更新資料**。兩者皆提供預設映射，匯入時仍由使用者確認，不依固定欄序。

必要藥品註記對照（設定 `annotation_code_map`）：不可替代特殊藥品→3、特殊藥品→4（代碼4「其他特殊藥品」＝系統類別「特殊藥品」）。【已確認】使用者 2026-10-17 確認。

> 月檔另有「特殊品項」欄（Y/N/A–F），對應 DWM_DRUG.DRUG_SPEC_MARK（特殊品項註記），**不是**本系統的註記，未用於比對。

### 需業務確認的發現

1. **月檔 price11510 與 DRPAY(115/10/01) 有 9 筆不同**：
   - BC27705214（2759 vs 2621）、BC27750100（12 vs 11.8）、BC28181100／BC28182100（11.5 vs 10.9）、VC00060100（30749 vs 30513）——DRPAY 有 115/10/01 起新價，月檔仍為舊價，推測月檔產製時點早於調價生效。
   - A035045100、B019563100、BC216431G0：月檔價格空白、DRPAY 為 0。
   → 以哪個來源、哪個基準日當價格依據，需確認；系統一律記錄來源檔與基準日。
2. **分組代碼缺值 1,384 筆、ATC 缺值 144 筆**：依規格「缺值＝待確認」，每條分組規則都會出現約 1,384 筆待確認。已提供「依待確認原因批次人工確認」（須理由、留稽核）。若業務同意「分組代碼缺值即不符合」，屬規則語意變更，需另確認。
3. **活頁簿1 第 250–288 列「篩選原則」為 Excel 公式**（`="分組代碼="&C250`）：移轉讀取 Excel 已存的計算結果；若檔案未經 Excel 存檔計算，該欄會空白並列待確認。
4. 活頁簿1 規格已點名的特殊情形，解析器皆標示待確認、不自動修正：Warfarin「同廠牌」跨列條件與末尾「=0」（3 列）、RO5DA04 疑似 O／0（1 列）、類別混合文字（6 列）、Rufinamide 非認列（第 172 列，有取消註記，不建立認定）、第 43 列「不可替代必要藥品(取消不可替代特殊藥品)」改列待確認。
5. 活頁簿1 特殊藥品生效日期 279/287 列空白 → 移轉後認定版本全為草稿＋不完整，不推定生效。
